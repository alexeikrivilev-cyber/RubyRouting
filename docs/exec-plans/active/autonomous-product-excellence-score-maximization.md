## Goal

Autonomously move the product toward the maximum defensible Hack.Genesis score while preserving one coherent smart-routing architecture. This plan records current evidence, priority and residual risk; it is intentionally not a predetermined patch sequence.

The agent is expected to discover issues not listed here, re-rank work after evidence, and improve the plan itself.

## Opening routine

At every session start:

1. fetch exact `main`, exact-head CI and generated root artifacts;
2. inspect authoritative TZ/rubric, organizer data/scripts and current submission profile;
3. inspect Case input/hard-gate/state/scoring/router/lifecycle/report/release code and relevant tests;
4. run a short skeptical code-first discovery sweep before trusting this plan;
5. reconstruct/update `COMPETITION_SCORECARD`, requirement matrix and finding registry from reality;
6. choose the highest expected-value material hypothesis or tightly coupled cluster.

## Priority model

Rank findings using:

- rubric points at risk/gain;
- correctness severity;
- confidence and hidden-test likelihood;
- judge visibility/product-story benefit;
- implementation/regression cost;
- whether the change simplifies or complicates semantic authority.

A new P0/P1 outranks every existing finding. Rewrite this plan when evidence changes priority.

## Technical product vector

Prefer improvements that strengthen one of these layers:

1. **Opportunity** — absolute typed hard constraints and correct fallback recheck.
2. **Portfolio objective** — stable exact configured multi-objective semantics with no hidden preference.
3. **Execution cascade** — one chooser, clean assignment/attempt/outcome/final/settlement lifecycle.
4. **Evidence/analytics** — causal explanations, feasibility diagnosis and quantitative counterfactual recommendations.
5. **Judge/release evidence** — deterministic rubric scenarios and fail-safe artifact provenance.

A change that adds code but does not improve a scored/protected layer is probably the wrong next task.
